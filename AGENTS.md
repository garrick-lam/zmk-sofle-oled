# AGENTS.md

ZMK firmware user config for the **Eyelash Sofle** keyboard (Sofle v2-style split keyboard with OLED display, trackball support via pointer devices, RGB underglow, EC11 encoders). Firmware is built automatically with GitHub Actions; no local toolchain is required for normal work.

## Repository Layout

```
config/
  eyelash_sofle.keymap      # Main user keymap (layers, behaviors, combos) — START HERE for keymap changes
  eyelash_sofle.conf        # Kconfig: ZMK features (display, pointing, RGB, sleep, soft-off, etc.)
  eyelash_sofle.json        # Physical layout definition used by ZMK Studio / keymap editor
  west.yml                  # ZMK / Zephyr module versions (pinned ZMK revision)
boards/shields/eyelash_sofle/
  eyelash_sofle.dtsi        # Shield hardware definition: matrix, diodes, encoders, pointer, display, RGB
  eyelash_sofle-layouts.dtsi# Physical layout node
  *_left/right.overlay|conf # Per-side device tree overlay + Kconfig
  eyelash_sofle.keymap      # Default/fallback keymap inside the shield (usually leave as-is)
build.yaml                  # Legacy build manifest (checked by ZMK build workflow in some setups)
.github/workflows/build.yml # Builds firmware via zmkfirmware/zmk build-user-config.yml@v0.3.0
.github/workflows/draw.yml  # Regenerates keymap-drawer SVGs
keymap-drawer/              # Generated visual keymap docs (SVG + YAML input)
docs/                       # Hardware docs, 3D models, firmware binaries (mostly Chinese filenames)
```

## Conventions

- ZMK Django-style devicetree syntax: `&kp`, `&mt`, `&mo`, `&trans`, `&mkp`, `&mmv`, `&msc`, `&bt`, `&rgb_ug`, `&soft_off`, etc.
- Layers in `config/eyelash_sofle.keymap`: MAIN (base), NAV (navigation/mouse on layer_0), NUM (keypad on layer_1), BT (Bluetooth on layer_2).
- Keys use ZMK binding constants with a trailing space before the key token (e.g., `&kp LSHFT`); keep the aligned-columns formatting of the keymap rows (each row is one physical row of 13 keys; bottom thumb row has 12).
- Hold-tap behaviors defined in the keymap root node (e.g., `caplock_hold_tap` — `flavor = "balanced"`, `tapping-term-ms = <150>`), not in `behaviors {}` (that block is intentionally empty).
- Extra behaviors must also be exposed in `config/eyelash_sofle.json` for ZMK Studio compatibility.
- `softoff` combo exists at key-positions `14 28 40` (hold 2s per `&soft_off { hold-time-ms = <2000>; }`).
- Pointer/scroll tuning constants are defined at the top of `config/eyelash_sofle.keymap` (`ZMK_POINTING_DEFAULT_MOVE_VAL`, `ZMK_POINTING_DEFAULT_SCRL_VAL`) plus `&mmv`/`&msc` node properties.
- Comments in the keymap often show previous/tuned values like `// 600` — preserve this style when re-tuning.

## Building / Testing

- Pushing any change triggers `.github/workflows/build.yml`; firmware artifacts appear under the workflow run. `build.yaml` lists expected builds if present.
- Updating `config/west.yml` changes the pinned ZMK version — behavior/feature availability depends on that revision.
- `keymap-drawer/*.svg` are regenerated by CI (`draw.yml`); edit `keymap-drawer/*.yaml` or the root `keymap_drawer.config.yaml`, never the SVGs by hand.

## Gotchas

- `config/eyelash_sofle.keymap` is the active config; the copy in `boards/shields/...` is a default and can silently differ.
- NKRO is disabled (`CONFIG_ZMK_HID_REPORT_TYPE_NKRO=n`) for compatibility with pointing mode.
- Devicetree/Kconfig errors only surface at CI compile time — verify syntax (semicolons, `< >`, `=&behavior-name`) carefully; there is no local linter.
- `.DS_Store` files and the firmware binaries / 3D models under `docs/` are user-owned; treat them as read-only references, never delete or reorganize them.
